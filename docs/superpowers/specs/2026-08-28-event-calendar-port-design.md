# Перенос «Афиши» (календаря событий) со старого сайта

Дата: 2026-08-28
Ветка: task-4
Референс старого дизайна: http://dev.infomania.ru (блок «Афиша» на главной)

## 1. Цель и контекст

На старом сайте блок «Афиша» — это **широкий** горизонтальный блок под герой-каруселью:
слева месячный календарь, справа панель контента. Панель показывает либо
пустое состояние («Сегодня можете взять книги» + иллюстрация), либо список
событий выбранного дня, либо карточку конкретного события.

На текущем новом сайте (`app/pages/index.vue`) в правой колонке герой-секции
(3 из 12) друг над другом стоят:
- `LazyInfoBanner` — карусель уведомлений (`success | warning | error | festive`) из `/api/notification/`;
- `LazyEventCalendar` — узкий календарь + список «Ближайшие события».

`EventCalendar.vue` уже умеет переключать виды `calendar | list | detail` с
анимацией, но он узкий и визуально не совпадает со старым решением.

### Задача

1. Переписать `EventCalendar` под **широкий side-by-side** макет старой «Афиши».
2. Контент `InfoBanner` (карусель уведомлений) встроить в **пустое состояние**
   правой панели «Афиши» + добавить строку статуса библиотеки.
3. Перенести **сезонную логику выходных дней** (оранжевая пометка).
4. Переверстать герой главной: `MainCarousel` на всю ширину, «Афиша» —
   отдельная полноширинная секция.

## 2. Решения (согласовано с заказчиком)

| Вопрос | Решение |
|---|---|
| Размещение «Афиши» | Отдельная полноширинная секция под героем, до блока поиска |
| Герой-карусель | `MainCarousel` на всю ширину (col-span-12), правая колонка убирается |
| Куда InfoBanner | В пустое состояние правой панели «Афиши» (карусель уведомлений + строка статуса) |
| Пометка выходных | Сезонная логика: сен–май — понедельник, июн–авг — воскресенье; последний день месяца — техдень |
| Библиотека календаря | Остаёмся на `UCalendar` (Nuxt UI, уже в проекте), `v-calendar` НЕ добавляем |

## 4. Компоненты

### 4.1 `EventCalendar.vue` (переписать) — оркестратор

Ответственность:
- Обёртка-карточка (`bg-white shadow rounded-xl overflow-hidden`).
- Единая шапка (как на старом сайте): заголовок «Афиша» + элементы навигации.
  - вид `calendar`: стрелки ‹ › для смены месяца, по центру — название месяца;
  - вид `list` / `detail`: слева стрелка «назад», справа крестик «сброс».
- Стейт-машина вида: `view = detail ? 'detail' : dayEvents ? 'list' : 'calendar'`
  (логика уже есть в текущем файле — переиспользуем).
- Загрузка событий за видимый месяц (см. §6).
- Раскладка тела:
  - **desktop (`lg:` и выше)**: `flex` — `EventCalendarGrid` (ширина ~360px,
    `shrink-0`) + `EventPanel` (`flex-1`). Календарь виден всегда, панель
    справа меняет содержимое.
  - **mobile**: показывается только `EventCalendarGrid`; при выборе дня —
    только `EventPanel` (swap через `<Transition>` `nav-forward`/`nav-back`,
    стили переходов уже есть в текущем файле).
- `headerTitle`:
  - `calendar` → «Афиша»
  - `list` → дата дня (`D MMMM`, напр. «21 августа»)
  - `detail` → заголовок события

Убираем из текущей реализации: отдельный «мобильный список upcomingEvents»
и блок «Ближайшие события» под сеткой (это была компенсация узкой колонки;
в широком макете правая панель этим и занимается). `upcomingEvents` можно
удалить.

### 4.2 `EventCalendarGrid.vue` (новый) — календарная сетка

Пропсы:
- `modelValue: CalendarDate` — текущий месяц/выбранная дата (v-model);
- `eventsByDate: Record<string, Event[]>` — карта событий по `YYYY-MM-DD`.

Эмиты:
- `select-day: Event[]` — клик по дню с событиями.

Внутри — `UCalendar` с `:year-controls="false"` `:month-controls="false"`,
слот `#day`:
- **день с событиями**: `UChip` с числом событий (color `info`), кружок
  `bg-info/20 text-info hover:bg-info/30 cursor-pointer`, клик →
  `emit('select-day', eventsByDate[key])`;
- **выходной** (`useLibrarySchedule().isDayOff(day)`): `bg-warning/20 text-warning`;
- **сегодня**: добавляется `ring-2 ring-primary`;
- **день вне месяца**: `text-gray-300`, не кликается;
- приоритет состояний: событие > выходной > сегодня-кольцо (кольцо
  добавляется поверх любого состояния текущего месяца).

Под сеткой — легенда:
```
● событие   ● выходной
```
(точки `bg-info` / `bg-warning`, `text-[11px] text-gray-400`).

Смену месяца родитель делает сам (кнопки в шапке `EventCalendar`), меняя
`modelValue`; grid реагирует на изменение и подсвечивает по актуальной карте.

### 4.3 `EventPanel.vue` (новый) — правая панель

Пропсы:
- `dayEvents: Event[] | null`
- `selectedEvent: Event | null`

Эмиты:
- `select: Event`

Рендер:
- `!dayEvents && !selectedEvent` → `<EventCalendarEmpty />`
- `dayEvents && !selectedEvent` → список дня (см. `EventDetail`, режим списка)
- `selectedEvent` → карточка события (см. `EventDetail`, режим детали)

По сути тонкая обёртка над `EventDetail` + `EventCalendarEmpty`. Можно
не выделять отдельный файл, а разместить условие прямо в `EventCalendar`
(решение на этапе реализации — если `EventCalendar` не раздувается).

### 4.4 `EventCalendarEmpty.vue` (новый) — пустое состояние

Верстка:
```
┌───────────────────────────────┐
│  <InfoBanner />                │   ← карусель уведомлений, h-full/flex-1
│  ───────────────────────────   │
│  [icon] Сегодня можете взять   │   ← строка статуса из useLibrarySchedule
│         книги                  │
```

  - иначе → иконка `i-heroicons-x-circle`, текст `text-warning`,
    «Сегодня библиотека не работает».

### 4.5 `EventDetail.vue` (доработать)

Текущий компонент уже покрывает оба режима (список / деталь). Доработки:
- Режим **детали**: слева вертикальная колонка-«ухо» (как на старом сайте):
  `день` (крупно) / `мес.` / `(дн)` / `время`. Справа — заголовок, `v-html`
  контент (класс `tiptap`), место (`IBillboardPlaces[place]`), телефон
  (`tel:`-ссылка), бейдж возраста `{age}+`.
- Режим **списка**: шапка «21 авг.» + строки `время — заголовок`
  (текущая вёрстка подходит, минимальные правки под стиль старого).
- Форматирование времени/дат — через `useParseEventTime` (уже используется).

### 4.6 `InfoBanner.vue` (минимальная правка)

- Внешняя обёртка: высота гибкая (`h-full` / `flex-1` вместо жёстких
  `h-28 sm:h-32 md:h-36`), чтобы вписаться в панель. Точную высоту
  подобрать при вёрстке.
- Логика (fetch уведомлений, `empty`-заглушка, типы/цвета) — без изменений.
- Компонент остаётся самостоятельным и переиспользуемым.

### 4.7 `useLibrarySchedule.ts` (новый composable)

Чистая дата-логика по расписанию из `app/components/modals/WorktimeLibrary.vue`:

```
C 1 сентября по 31 мая:  вт–пт 10:00–20:00, сб–вс 10:00–19:00, пн — выходной
C 1 июня по 31 августа:  пн–сб 10:00–19:00, вс — выходной
Последний день месяца — технический день.
```

API:
- `dayOffWeekday(date): number` — день недели-выходной для месяца даты
  (`dayjs().day()`: 0=вс, 1=пн). Месяцы 6–8 → `0`; месяцы 9–12, 1–5 → `1`.
- `isDayOff(date): boolean` — `dayjs(date).day() === dayOffWeekday(date)`
  **или** `date` — последний день своего месяца (техдень).
- `canBorrowToday(): boolean` — `!isDayOff(сегодня)`.
- `statusText: ComputedRef<string>` — «Сегодня можете взять книги» /
  «Сегодня библиотека не работает».
- `statusTone: ComputedRef<'success' | 'warning'>`.

Без обращений к API. Даты — через `dayjs` (локаль `ru` уже настроена).

## 5. Календарная сетка — состояния дня (сводка)

| Состояние | Условие | Оформление | Клик |
|---|---|---|---|
| Событие | `eventsByDate[key]?.length` | синий кружок + `UChip` с числом | → список/деталь дня |
| Выходной | `isDayOff(day)` | `bg-warning/20 text-warning` | нет действия |
| Сегодня | `isToday(day)` | `ring-2 ring-primary` поверх | как у базового состояния |
| Вне месяца | `day.month !== calendarDate.month` | `text-gray-300` | нет |
| Обычный | — | без оформления | нет |

Приоритет фонового стиля: событие > выходной > обычный. Кольцо «сегодня»
добавляется независимо (для дней текущего месяца).

## 6. Данные

### События
- Заменить сырой `$fetch(config.public.apiBaseUrl + '/api/event', …)` в
  `EventCalendar.vue` на сервис `useEventApi().getAllEvents(params)`
  (`services/api/eventService.ts`, endpoint `API_ENDPOINTS.event`).
- Параметры: `{ startDate: <начало месяца ISO>, endDate: <конец месяца ISO>, limit: 100 }`.
- Границы месяца — `dayjs(calendarDate).startOf('month') / endOf('month')`.
- Ответ — `ApiResponse<Event[]>`; группируем в `eventsByDate` по ключу
  `useParseEventTime(event.eventTime).format('YYYY-MM-DD')`.
- Перезапрос при смене месяца.
- Первичная загрузка — `onMounted` (клиентский рендер, как сейчас), либо
  `useAsyncData` для SSR — решение на этапе реализации, приоритет — не
  сломать гидрацию.

### Уведомления
- `useNotificationApi().getAllNotifications({ limit: 5 })` — уже внутри
  `InfoBanner.vue`, без изменений.

### Расписание
- `useLibrarySchedule` — без API.

## 7. Адаптивность

- **`lg` и выше**: календарь (`~360px`, `shrink-0`) + панель (`flex-1`) в один ряд.
  Календарь виден всегда; панель справа переключает пусто/список/деталь.
- **ниже `lg`**: виден только календарь; выбор дня — swap на панель на всю
  ширину блока, крестик «назад к календарю» в шапке. Переходы
  `nav-forward` / `nav-back` (CSS уже в текущем `EventCalendar.vue`).
- Высота секции — по контенту; внутренние списки/контент события — со
  скроллом (`max-h-[...] overflow-y-auto`).

## 8. Вне области задачи (YAGNI)

- Не добавляем зависимость `v-calendar`.
- Не трогаем `Header`, `Footer`, прочие секции главной, страницы событий.
- Отдельная страница «Все события» не делается. Ссылку в шапке секции
  (`CommonSectionWrapper link`) на `/post/search?rubric=sobytiya` добавить,
  только если такой роут реально существует в проекте (проверить при
  реализации); иначе шапка секции — без ссылки.
- Тесты не пишем — в проекте нет тестовой инфраструктуры (CLAUDE.md).

## 10. Критерии готовности

- На десктопе главной под героем — широкий блок «Афиша»: слева календарь,
  справа панель.
- Дни с событиями помечены синим с числом; выходные (по сезону) — оранжевым;
  сегодня — кольцом.
- Клик по дню с событиями открывает список → карточку события; крестик и
  «назад» работают.
- Когда день не выбран — в панели карусель уведомлений + строка статуса
  библиотеки.
- На мобильном виден календарь, выбор дня разворачивает панель с «назад».
- Герой-карусель — на всю ширину; старая правая колонка удалена.
- `npx eslint .` без ошибок по изменённым файлам; `npm run build` проходит.
