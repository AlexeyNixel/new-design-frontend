# Промт: перевод существующей страницы из HTML в блочный формат

Как пользоваться:

1. Скопируй промт ниже целиком (от `─── НАЧАЛО ПРОМТА ───` до `─── КОНЕЦ ПРОМТА ───`).
2. В конце вставь исходный HTML страницы (из админки / поля `content` / базы).
3. Отправь в Claude Code (или любую LLM с доступом к этому репозиторию — так она сверится с типами и компонентами).
4. На выходе — валидный JSON-массив `blocks`, который кладётся в `page.blocks` (ответ API `GET /pages/:slug` или поле в админке). Поле аддитивное: `content` остаётся, страница начинает рендериться блоками автоматически (см. `docs/page-content-blocks.md`).

Контекст в коде, с которым сверяется модель:

- Типы (единственный источник правды по контракту): `services/types/page.type.ts`
- Компоненты блоков: `app/components/page-blocks/*.vue`
- Диспетчер: `app/components/page-blocks/Renderer.vue`
- Эталон готовой страницы на блоках: `app/pages/page/mediateka.vue`
- Обработчик обоих форматов: `app/pages/page/[slug].vue`

Ты переводишь существующую страницу сайта Новосибирской областной молодёжной
библиотеки из свободного HTML в блочный формат «page builder».

## Задача

На входе — HTML-контент одной страницы отдела (то, что сейчас лежит в поле
`page.content` и рендерится через `v-html`). Нужно разобрать его на
упорядоченный массив типизированных блоков и вернуть **только** валидный JSON —
массив `PageBlock[]`, без обёрток, без комментариев, без markdown-ограждения.

Если проект доступен — сверь формат с `services/types/page.type.ts`
(discriminated union по полю `type`) и с вёрсткой компонентов
`app/components/page-blocks/*.vue`. Эталон итогового набора блоков —
`app/pages/page/mediateka.vue`.

## Типы блоков

Первым элементом массива, как правило, идёт `hero` (шапка страницы, рендерится
на всю ширину, вне белой карточки). Остальные блоки идут по порядку внутри
карточки-контейнера.

| `type`       | Поля | Что это визуально | Когда применять к HTML |
|--------------|------|-------------------|------------------------|
| `hero`       | `title` (обяз.), `subtitle?`, `label?`, `icon?`, `contacts?: { phone?, address?, email?, workHours? }` | Большой заголовок на фоне `primary` + опциональная белая карточка с контактами | Заголовок страницы (`<h1>`) + вводная фраза + блок контактов отдела, если он есть в тексте |
| `stats`      | `items: { value, label }[]` | Сетка карточек с крупной цифрой и подписью | Перечисления вида «10 000+ грампластинок», «300+ мероприятий в год», «5 клубов» |
| `features`   | `items: { title, description, icon? }[]` | Сетка карточек (2 колонки) с иконкой, заголовком и абзацем | Список направлений / услуг / возможностей, где у каждого пункта есть название и описание |
| `tags`       | `title?`, `items: string[]` | Ряд «пилюль» (pill) в цвете `primary/10` | Короткие подписи одной строкой: коллекции, категории, жанры, форматы |
| `advantages` | `title` (обяз.), `items: string[]` | Серый блок со списком, у каждого пункта — галочка | «У нас есть всё, чтобы…», условия, преимущества, что предоставляется |
| `highlight`  | `title` (обяз.), `description` (обяз.), `badge?` | Акцентный блок целиком в цвете `primary`, по центру | Анонс проекта / гранта / отдельной инициативы внутри страницы |
| `person`     | `name` (обяз.), `position` (обяз.), `icon?` | Карточка с иконкой и подписью «Руководитель отдела» | Упоминание руководителя / главного библиотекаря отдела (ФИО + должность) |
| `banner`     | `text` (обяз.) | Финальная «пилюля» в цвете `primary` по центру | Завершающая фраза-приглашение в самом конце страницы |
| `archive`    | `title` (обяз.), `note?`, `items: { date?, text, url }[]` | Свёрнутый по умолчанию аккордеон со счётчиком; развёрнутый список скроллится внутри | Длинные списки датированных ссылок: архив выпусков проекта, подборки видео/новостей, плейлисты |
| `richText`   | `html` (обяз.) | Обычный форматированный текст (`prose`): абзацы, списки, ссылки, `<b>` | Всё, что не ложится в блоки выше: содержательные абзацы, пояснения, исторические справки |

## Правила разбора

1. **Порядок сохраняется.** Блоки идут в том же порядке, в каком
   соответствующий контент встречается в HTML.
2. **Текст не выдумывать и не сокращать.** Переносим формулировки как есть.
   Можно только: убрать пустые обёртки, разбить сплошную «простыню» на абзацы,
   исправить очевидную битую разметку. Не добавляй факты, которых нет в
   исходнике (телефоны, адреса, имена, цифры).
3. **`hero` почти всегда нужен.** В блочном формате при наличии `hero`
   заголовок берётся из `hero.title`, отдельный `<h1>` и хлебные крошки не
   выводятся. `label` — короткая надпись-бейдж («Отдел медиатека»),
   `subtitle` — одна вводная фраза. `contacts` добавляй только если контакты
   реально есть в тексте; отсутствующие поля контакта просто не указывай.
4. **`richText` — запасной вариант.** Сначала пытайся выделить структурные
   блоки (`stats`, `features`, `tags`, `advantages`, `highlight`, `person`,
   `banner`, `archive`); в `richText` уходит только то, что осталось. Несколько
   абзацев подряд без структуры — это один `richText` с несколькими `<p>`, а не
   несколько блоков.

4a. **Датированные списки ссылок → `archive`, не `richText`.** Любой перечень из
   пунктов вида «дата + ссылка на выпуск/новость/видео» (архив проекта, плейлист,
   подборка эфиров) — это блок `archive`: `title` — название архива/проекта,
   `note` — сопроводительная строка (например грантовая сноска), `items` — по
   объекту `{ date?, text, url }` на ссылку. `date` — строкой в формате
   `ДД.ММ.ГГГГ`. Из `text` можно убрать повторяющийся во всех пунктах хвост
   (название проекта уже в `title`) — это единственное допустимое сокращение.
   Не сваливай такие списки в `richText`.
5. **`features` vs `tags`.** Есть заголовок + описание у каждого пункта →
   `features`. Только короткие ярлыки в одну строку → `tags`.
6. **`stats`.** Только если в тексте явно есть числовые показатели.
   `value` — само число со знаком/суффиксом (`«10 000+»`, `«5»`), `label` —
   подпись (`«грампластинок»`). Не выдумывай метрики.
7. **`advantages` vs `features`.** Плоский перечень строк (пусть и длинных),
   вводимый фразой типа «У нас есть всё, чтобы…», «Мы предлагаем:» →
   `advantages` (заголовок = эта вводная фраза, `items` = пункты).
8. **`person`.** ФИО + должность руководителя отдела. Подпись «Руководитель
   отдела» добавляет сам компонент — в данные её не класть.
9. **`banner`.** Только одна финальная фраза-приглашение в самом конце.
   Не делай `banner` из середины текста.
10. **Иконки.** Значения `icon` — имена Heroicons в формате `i-heroicons-<name>`
    (например `i-heroicons-film`, `i-heroicons-musical-note`,
    `i-heroicons-book-open`, `i-heroicons-academic-cap`, `i-heroicons-user-group`,
    `i-heroicons-user-circle`, `i-heroicons-sparkles`, `i-heroicons-calendar-days`).
    Подбирай по смыслу; если подходящей нет — поле `icon` можно опустить.
11. **`richText.html`** — валидный HTML только из простых тегов: `<p>`, `<b>`,
    `<i>`, `<ul>/<ol>/<li>`, `<a href>`, `<br>`. Без `style`, `class`, `<div>`,
    `<span>`, инлайновых атрибутов оформления, без `<h1>` (заголовок — это
    `hero`; подзаголовки внутри текста — `<b>` или `<h3>`).
12. **Без дублей внутри блока.** В `tags`/`advantages`/`stats`/`features`
    строки-элементы в пределах одного блока не должны повторяться (они идут
    ключами списка).
13. **Единый акцент.** Дизайн блоков одноцветный — только `primary` +
    нейтральные. Никакой цветовой параметризации в данных быть не должно
    (её и негде указать).

## Формат вывода

Строго один JSON-массив. Пример структуры (значения — иллюстративные):

```json
[
  {
    "type": "hero",
    "icon": "i-heroicons-musical-note",
    "label": "Отдел медиатека",
    "title": "Медиатека",
    "subtitle": "Место встречи всех, кто любит кино и музыку",
    "contacts": {
      "phone": "+7 (383) 210-12-04",
      "address": "г. Новосибирск, Красный проспект, 26",
      "workHours": "Пн–Пт 10:00–19:00"
    }
  },
  { "type": "stats", "items": [
    { "value": "10 000+", "label": "грампластинок" },
    { "value": "1000+", "label": "фильмов на дисках" }
  ]},
  { "type": "richText", "html": "<p><b>Медиатека</b> располагает обширной коллекцией фильмов на лицензионных дисках…</p>" },
  { "type": "features", "items": [
    { "icon": "i-heroicons-film", "title": "Коллекция фильмов", "description": "Киноклассика, новинки, документальное кино." }
  ]},
  { "type": "tags", "title": "Коллекции фильмов в сериях:", "items": ["Театр на экране", "Балетные постановки"] },
  { "type": "advantages", "title": "У нас есть всё для отдыха и работы:", "items": ["Открытый доступ к фонду", "Зал для групповых просмотров"] },
  { "type": "highlight", "title": "Мульт-Сибирь", "description": "В медиатеке работает мультстудия в рамках проекта…", "badge": "🎬 Присоединяйтесь!" },
  { "type": "person", "name": "Бычкова Наталья Васильевна", "position": "главный библиотекарь", "icon": "i-heroicons-user-circle" },
  { "type": "archive", "title": "Открытое пространство: А что там за обложкой?",
    "note": "Проект реализуется в рамках гранта Благотворительного фонда Владимира Потанина.",
    "items": [
      { "date": "17.04.2026", "text": "Тридцать третий выпуск с Дмитрием Бобиным", "url": "https://vkvideo.ru/video-5693391_456240783" },
      { "date": "03.04.2026", "text": "Тридцать второй выпуск с Натальей Стригуновой", "url": "https://vkvideo.ru/video-5693391_456240780" }
    ]
  },
  { "type": "banner", "text": "Всегда рады видеть вас в медиатеке! 🎬🎵" }
]
```

После JSON добавь короткий список (обычным текстом, вне JSON): какие фрагменты
исходного HTML никуда не попали или требуют ручной проверки (контакты, ссылки,
изображения, таблицы) — чтобы я мог свериться.
