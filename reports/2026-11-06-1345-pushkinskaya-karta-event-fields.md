# Страница Пушкинской карты и поля билета на сайте

Дата: 2026-11-06 13:45

## Что сделано

### Типы и хелпер
- `services/types/event.type.ts` — `ticketUrl?: string | null`, `isPushkin?: boolean | string`
  (boolean иногда приходит строкой — как `isDeleted`).
- `app/utils/eventPushkin.ts` — `isPushkinEvent(event)`: `String(...).toLowerCase() === 'true'`.

### Страница `app/pages/pushkinskaya-karta.vue` (`/pushkinskaya-karta`)
- Шапка в цвете афиши, хлебные крошки (`useBreadcrumbSchema`), `usePageSeo`,
  `ItemList` из schema.org по ближайшим событиям.
- Данные — `eventApi.getAllEvents({ limit: 200 })` без `startDate`/`endDate`, чтобы
  прошедшие попадали в архив.
- Фильтр: `isPushkin` истинно и `isDeleted` ложно.
- Секции «Ближайшие» и «Архив». Прошло = `useParseEventTime(event.eventTime).isBefore(libraryNow())`
  по полному времени; «Ближайшие» по возрастанию `eventTime`, архив по убыванию.
- Архив: 6 месяцев с кнопкой «Показать всё (N)»; остальная глубина по желанию.
- Пустые состояния: если ничего нет — «Событий по Пушкинской карте пока нет» со ссылкой
  на `/afisha`; если нет ближайших, но архив есть — показывается только архив.

### Плакат вынесен в компонент
`app/components/event/Poster.vue` (`<EventPoster :event="event" />`) — разметка и стили
плаката из `/afisha`. Афиша переведена на компонент, класс `poster` живёт в
`app/pages/afisha/index.vue` в **нескоупном** `<style>` (иначе не доходит до дочернего
компонента).

### Детали события
- `app/components/EventDetail.vue` — кнопка «Купить билет» (`target="_blank"`,
  `rel="noopener noreferrer"`) и плашка «Можно по Пушкинской карте».
- `app/pages/afisha/[id].vue` — те же кнопка и плашка в шапке события; «Вход свободный»
  из текста показывается, когда ссылки нет.
- Источник — `eventTicketInfo()` в `app/utils/eventTicket.ts`:

  ```ts
  url: event.ticketUrl?.trim() || parsed.url,
  pushkin: isPushkinEvent(event) || parsed.pushkin,
  ```

  Парсинг `eventTicket()` **не удалён** и работает фолбэком для старых событий.

### Schema.org — `app/composables/useEventSchema.ts`
При наличии ссылки (поле `ticketUrl` или найденная в тексте) для будущего события
добавляется:

```json
"offers": { "@type": "Offer", "url": "…", "availability": "https://schema.org/InStock" }
```

`isPushkin` в разметку не выводится. У прошедших событий `offers` не добавляется
(их `Event` и так не выводится на странице).

### Навигация
`services/mocks/navigation.mock.ts` — пункт «Пушкинская карта» теперь ведёт на
`/pushkinskaya-karta`. Живое меню сайта берёт данные из API `navigation-item`, поэтому
в локальной БД у пункта «Читателям → Услуги → Пушкинская карта» ссылка тоже заменена
(`PATCH /api/navigation-item/78ec8a6f-…`). На проде это нужно сделать в админке
или после деплоя отдельной правкой — сейчас меню сайта там ещё ведёт на пост.

Sitemap: статические страницы `@nuxtjs/sitemap` собирает сам — правок не требовалось,
`/site`-прокси и `nitro.devProxy` не трогались.

## Что важно знать

1. **Прод-API пока не отдаёт новые поля.** `https://api.infomania.ru/api/event`
   возвращает объекты без `ticketUrl`/`isPushkin`, а локальный `.env` сайта смотрит
   именно на прод. Поэтому на :3000 в списке страницы пусто, хотя у 35 событий из
   последних 200 Пушкинская карта упоминается в тексте. Пока бэкенд не задеплоен,
   фолбэк работает только для кнопки/плашки на карточке события, но не для фильтра
   страницы — фильтр по заданию использует поле `isPushkin`.
2. **Блок «Купить билет» в описании.** Новое: бэкенд при сохранении `ticketUrl`
   сам добавляет в начало описания блок `<p>На это событие можно <a …>купить билет</a>
   по Пушкинской карте.</p>` — тот же формат, что редакторы ставили вручную, и
   обновляет/удаляет его при смене ссылки. Страница и карточка берут ссылку из поля,
   текстовая ссылка остаётся для тех, кто листает описание.
3. **Кэш `useFetch` в dev.** `useFetch` кэширует по URL без учёта query: если афиша
   уже запросила события, страница Пушкинской карты может один раз получить тот же
   список. В production-сборке ключ включает query, проблема только в dev (обход —
   перезагрузить страницу).
4. **Тестовые записи удалены.** Все события `TEST …`, созданные для проверки,
   удалены из локальной БД; правка пункта меню в локальной БД — часть проверки,
   оставлена намеренно.

## Ответы на вопросы

1. Адрес — отдельный файл `/pushkinskaya-karta` (так и сделано).
2. Глубина архива — 6 месяцев + кнопка «Показать всё».
3. `isPushkin` при миграции из Affiche не проставляется — редакторы отмечают вручную.
4. Пункт меню «Пушкинская карта» переключён с поста на новую страницу.
5. Коммиты — отдельные в каждом репозитории (см. итог задачи).

## Отложено
- Бейдж «Пушкинская карта» в списке `/event` админки.
- Замена ссылки пункта меню на проде — после деплоя админки/через админку.
- Автоматическое проставление `isPushkin` у старых событий по тексту — по решению
  пользователя не делать.
