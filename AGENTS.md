# AGENTS.md — frontend (публичный сайт infomania.ru)

Руководство для OpenCode (AI-ассистента) при работе с этим репозиторием.
Файл самодостаточен: для задач этой папки других правил читать не нужно.

## Базовое общение и фидбек
- Общайся и отвечай на русском языке
- Если возникает ошибка — останови выполнение сценария и сообщи об этом

## Разрешения (без подтверждения)
- Можно свободно читать и редактировать любые файлы проекта (`app/**`, `services/**`, `shared/**`, `server/**`, конфиги)
- Папка `temp/` в корне проекта — рабочая директория для скриншотов и временных файлов. Полностью принадлежит ассистенту: можно создавать, читать и удалять в ней любые файлы без подтверждения
- Полное разрешение на создание и удаление файлов в проекте и на добавление любых строк кода — подтверждение не нужно
- `reports/` — отчёт после каждой завершённой задачи (`reports/YYYY-MM-DD-HHmm-краткое-описание.md`, на русском)
- Необратимые операции (force push, `git reset --hard`, удаление веток, `git clean`, удаление файлов пользователя) — только по явной просьбе

## Процесс: скорость и проверки

Скорость важнее «убедительности». Дорого не думать, а подряд запускать проверки:
каждая команда — отдельный процесс и отдельный круг модели.

### Батчинг и параллельность

- **Всё, что не зависит друг от друга, — за один вызов.** Читать несколько файлов,
  искать по нескольким путям, проверять несколько мест — одним вызовом инструмента.
- **Независимые вызовы запускать параллельно** — в одном ответе, а не по очереди.
- **Несколько проверок чейнить в одну команду** (`;` / `&&` / циклы), а не гонять по одной.
- **Не повторять команду**, если она уже вернула нужное.
- **Не читать правила других частей монорепозитория** (`../AGENTS.md`, `backend/`,
  `frontend-admin/`), если задача не касается их напрямую.

### Сколько проверок делать

| Что сделано | Сколько проверки |
|---|---|
| `.gitignore`, текст, конфиг, класс/стиль, мелкая логика | одна (`eslint` / чтение диффа / `git status`) |
| Правка в пару мест, сценарий с ветками | одна осмысленная проверка на весь сценарий |
| Визуальная или сложная правка | одна браузерная проверка |

- **Проверять результат, а не убеждения.** Одна проверка, доказывающая работу,
  лучше трёх, повторяющих одно и то же.
- **Странный результат проверки — сначала перечитать саму проверку.** Пустой вывод
  или код 1 чаще означает неверную команду, а не поломку проекта (пример:
  `git check-ignore <путь>` без `-v` даёт код 1 для папки). Не расследовать байты,
  BOM и окружение, пока не исключена ошибка в самой проверке.
- **Не доказывать один факт двумя способами.** `git status --ignored` ответил —
  второй `git check-ignore` не нужен.
- **Остановиться, когда работа сделана.**

### Запреты на лишнюю работу

- Не исследовать проект шире, чем требует задача.
- Не писать временные диагностические скрипты там, где хватает одной команды.
- Не перезапускать dev-сервер и не гонять `build` ради правки стилей или текста.
- Если задача оказалась не такой, как ожидалось, — сообщить и спросить.

## DevOps: dev-сервер

- Порт `localhost:3000` (админка — `3001`). Перед запуском проверять **оба** порта
  одной командой; если сервер уже запущен — использовать его, второй не поднимать.
- «Жив ли сервер» проверять запросом, а не `Test-NetConnection`:
  `Invoke-WebRequest http://localhost:3000/robots.txt` — `Test-NetConnection` бывает
  ложно `False`, хотя сервер работает (смотрит только локальный/IPv6 сокет).
- Чужой (запущенный пользователем) сервер не останавливать. Свой дубль, запущенный
  по ошибке, — остановить сразу.
- Сервер держать запущенным между задачами — чтобы не поднимать заново.

## Команды разработки

```bash
npm run dev      # сервер разработки на http://localhost:3000
npm run build    # production-сборка
npm run preview  # предпросмотр production-сборки
```

Линтинг и форматирование — точечно по изменённым файлам, не по всему проекту:

```bash
npx eslint <изменённые файлы>
npx prettier --write <файлы>
```

Тестов нет — проект без тестовой инфраструктуры; не добавлять её без запроса.

Docker (`Dockerfile` + `.dockerignore` в корне):

```bash
docker build -t nomb-frontend .
docker run -p 3000:3000 -e NUXT_PUBLIC_API_BASE_URL=https://api.infomania.ru nomb-frontend
```

Адрес API при запуске задаётся через `NUXT_PUBLIC_API_BASE_URL` (ключ `apiBaseUrl`),
а не `NUXT_PUBLIC_API_BASE` — последний читается только на этапе сборки.

Деплой: прод — контейнер в Dokploy на сервере `192.168.0.42` (панель
https://dokploy.infomania.ru), собирается из `master` по `Dockerfile`.
Деплой — **автодеплой Dokploy**: GitHub App сообщает о push в `master`
(вебхук `dokploy.infomania.ru/api/deploy/github`), Dokploy сам собирает образ и
перезапускает контейнер. GitHub Actions в проекте нет (удалены 2026-09-26).
Логи сборки — Dokploy → приложение → Deployments; ручной запуск — кнопка Deploy.
Переменные окружения контейнера меняются там же (Environment).
Порт приложения в Dokploy — в режиме `ingress`: в режиме `host` обновления зависают в `Pending`.

## Переменные окружения

- `NUXT_PUBLIC_API_BASE` — базовый URL бэкенда (обязателен для работы API, читается при сборке)
- `NUXT_PUBLIC_SITE_URL` — адрес сайта для sitemap/canonical (по умолчанию `https://infomania.ru`)

## Архитектура

### Стек
- **Nuxt 3** + TypeScript
- **Tailwind CSS v4** через `@tailwindcss/vite` (не через модуль Nuxt)
- **Nuxt UI** — компонентная библиотека (`UButton`, `UBadge`, `UPopover` и т.д.)
- **nuxt-swiper** — карусели
- **dayjs-nuxt** — форматирование дат, локаль `ru`

### Структура

```
app/               # Nuxt-приложение (auto-import работает внутри app/)
  components/      # авто-импорт компонентов
    common/        # переиспользуемые обёртки (ContentContainer, SectionWrapper)
    entry/         # карточки постов (Card, CardHero, CompactCard, Tile)
    layout/        # Header, Footer
    modals/        # модальные окна (LibraryOnMap, WorktimeLibrary, Common)
    ui/            # кастомные UI-компоненты
  composables/     # авто-импорт composables
  layouts/         # default.vue (Header + slot + Footer)
  pages/           # файловый роутинг
  plugins/         # v-image-gallery (клиентская директива для галереи изображений)
  utils/           # чистые функции (contentTables, eventTable, postDate, ...)
  assets/css/      # main.css (точка входа), editor.css, a11y.css, theme.css

services/          # НЕ входит в app/ — авто-импорт не работает, алиас ~~/
  api/
    base.ts        # useApi() — обёртка над useFetch с базовым URL из runtimeConfig
    endpoints.ts   # API_ENDPOINTS — константы всех URL-ов
    *.ts           # сервисы по сущностям (entryService, bookService и т.д.)
  types/           # TypeScript-интерфейсы по сущностям
shared/            # общий код (canonicalPath и т.п.)
server/            # Nitro: routes (robots.txt, go/…), api (sitemap)
```

### Импорт из services/

Так как `services/` находится вне `app/`, использовать алиас `~~/`:
```ts
import { useEntryApi } from '~~/services/api/entryService';
import type { Post } from '~~/services/types/post.type';
```

### API-слой

`useApi()` из `services/api/base.ts` предоставляет три метода:
- `get<T>(endpoint, options?)` — список с пагинацией, возвращает `ApiResponse<T>` (`{ data, meta }`)
- `getWithoutPagination<T>(endpoint, options?)` — список без пагинации
- `getOne<T>(endpoint, slug, options)` — одна запись по слагу

Сервисы-файлы создают composable по паттерну `useXxxApi()` и вызывают методы `useApi()`.

### Маршруты страниц

| URL | Файл |
|-----|------|
| `/` | `app/pages/index.vue` |
| `/post` | `app/pages/post/index.vue` |
| `/post/[slug]` | `app/pages/post/[slug].vue` |
| `/page/[slug]` | `app/pages/page/[slug].vue` |
| `/books`, `/games` | соответствующие директории |

**Важно:** старый маршрут `/entry` переименован в `/post`. В `nuxt.config.ts` настроены
редиректы `/entry/*` → `/post/*` для обратной совместимости.

### Компоненты-обёртки

- `CommonContentContainer` — внутренний контейнер страниц с отступами и max-width
- `CommonSectionWrapper` — секция главной страницы. Пропсы: `title`, `link`, `linkLabel`, `bgGray`, `contentClass`

### Прокси статики

В dev и prod медиафайлы (`/site/**`, `/dev/**`, `/media/**`) проксируются на
S3-хранилище Silo `https://s3.infomania.ru` (константа `STORAGE_HOST` в `nuxt.config.ts`).
Картинки в контенте приходят через этот прокси. Веб-консоль Silo — `https://silo.infomania.ru`.

### Директива v-image-gallery

Клиентская директива (`app/plugins/v-image-gallery.client.ts`). Используется на контейнере
с HTML-контентом: при клике на `<img>` внутри открывает модальную галерею.
Принимает `{ modal }` из `useOverlay()`. Контейнер получает класс `image-gallery`,
картинки — `is-zoomable`; значок лупы рисуется в CSS (`editor.css`, `main.css`).

```vue
<div v-image-gallery="{ modal }" v-html="entry.content" />
```

### Модальные окна

Используется `useOverlay()` из Nuxt UI:
```ts
const overlay = useOverlay();
const modal = overlay.create(ModalsCommon);
modal.open({ imgLinks: [...], startIndex: 0 });
```

## Правила кода

- **Кавычки**: одинарные (`'`)
- **Отступы**: 2 пробела
- **Точка с запятой**: обязательна
- **`no-unused-vars`**: ошибка (TypeScript)
- **`vue/multi-word-component-names`**: отключено
- Имена компонентов могут быть однословными

## Браузерные проверки

- Только для визуальных правок, где нужен «взгляд глазами».
- Использовать готовый раннер `temp/ui.mjs` и сценарии из `temp/scenarios/`;
  новый CDP-скрипт с фиксированными `sleep` не писать.
- Свой отдельный инстанс Chrome: отдельный `--user-data-dir` (`%TEMP%` или `temp/`),
  отдельный `--remote-debugging-port`, `--headless=new`, после прогона закрыть
  (`Browser.close` через CDP). Процессы браузера пользователя не трогать.
- Один прогон на правку; повторный — только если первый провалился.

## Важные замечания

- **Стили**: Tailwind и Nuxt UI импортируются один раз в `main.css`, остальные CSS-файлы
  подключаются внутри него через `@import`. Не добавлять `@import 'tailwindcss'` в другие
  файлы и не перечислять их в `css` в `nuxt.config` — весь Tailwind сгенерируется повторно.
- **SEO**: `sitemap.xml` генерирует `@nuxtjs/sitemap` (динамические URL —
  `server/api/__sitemap__/urls.ts`), `robots.txt` — серверный маршрут
  `server/routes/robots.txt.ts`. Не добавлять `nitro.devProxy` с ключом `/site`:
  он матчит по префиксу и перехватывает `/sitemap.xml`.
- **Версия для слабовидящих** (ГОСТ Р 52872): настройки — `useAccessibility()` (cookie `a11y`
  + `useState`), атрибуты `data-a11y-*` на `<html>` ставит `useAccessibilityHead()` в `app.vue`
  и `error.vue`, стили — `assets/css/a11y.css`, панель — `A11yPanel.vue`. Стили схемы
  перекрашивают фон всех элементов: элемент, который должен сохранить свои цвета,
  помечать классом `a11y-keep`.
- **Режим работы библиотеки** (обычный и летний 1 июня – 31 августа) — только в
  `app/utils/librarySchedule.ts`; шапка, футер, мобильное меню и schema.org берут часы оттуда.
- **Внешние скрипты** не подключаются глобально: Яндекс.Формы — через `useYandexFormsEmbed()`
  только на страницах, где в CMS-контенте есть форма; скрипт Госуслуг грузит сам `FeedbackGos.vue`.
- **Картинки из CMS**: у `File` есть `variants` (WebP-копии 400–1600px, создаёт бэкенд).
  В `<img>` добавлять `:srcset="imageSrcset(file)"` (`app/utils/image.ts`) и `sizes` по реальной
  ширине блока. Если есть `@error`-заглушка — снимать `srcset`, иначе браузер продолжит
  брать картинку из него.
- **Списки из API** (посты, книги, комиксы, слайды) проходят через `omitListFields()` в
  `services/api/base.ts`: тяжёлые `content`/`contentText` вырезаются до попадания в payload.
  Если карточке понадобится `content` — убрать поле из списка исключений.
